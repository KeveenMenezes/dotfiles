# Dotfiles Repository

This repository contains configuration files and scripts for customizing your development environment on macOS.

## Structure

- **aerospace/**
	- `default-config.toml`: Configuration for the AeroSpace window manager, including layout settings, and normalization options.

- **vs-code/**
	- `keybindings.json`: Custom keybindings for Visual Studio Code.
	- `settings.json`: User settings for Visual Studio Code.

- **ghostty/**
	- `config`: Ghostty terminal config. Opens straight into herdr, so reopening Ghostty reattaches to the running agents.
	- `themes/prom-wiki`: Prom-Wiki color theme for Ghostty.

- **herdr/** — [herdr](https://herdr.dev), terminal multiplexer built for AI coding agents
	- `config.toml`: Prometheus theme (promo-wiki palette over the Ghostty ANSI colors, transparent panels), nushell panes, agent sidebar with model/context for Claude, Claude plan quota in the tab bar, popups.
	- `scripts/claude-statusline.sh`: Claude Code `statusLine`. Reports model and context to the herdr sidebar, caches the plan quota (`rate_limits` 5h/7d) and prints a compact line inside Claude Code.
	- `scripts/claude-quota.sh`: tab bar segment that shows the cached quota (`5h 23% ↻ 1h14m · 7d 41%`).
	- `plugins/workflow/`: local herdr plugin `keveen.workflow` (linked by `install.sh`):
		- Ctrl+click on a GitHub PR/issue link opens a popup with `gh pr view` / checks / diff (delta) instead of the browser; `prefix ctrl+r` does the same for the PR of the focused pane's branch. Falls back to the other logged-in `gh` account when the active one can't see the repo.
		- on `worktree.created`, copies the git-ignored local files (`.env*`, `.envrc`, `*.local*`, `settings.local.json`, `.lazysql.toml`) from the main worktree into the new one and runs `direnv allow`. Never overwrites.
		- on server startup (including after `herdr update`), keeps `~/.claude/skills/herdr/SKILL.md` equal to `herdr --skill`.

- **claude/skills/** — Claude Code skills linked into `~/.claude/skills`: `background-panes` (live panes for background jobs) and `multi-agent-panes` (one monitor pane per subagent). The official `herdr` skill is generated from the installed binary, not versioned.

- **bin/task** + **task/** — work organized by task (see [Tasks](#tasks)). `task/lib.sh` holds the herdr/git helpers, `task/default-layout.sh` the generic per-repo layout, `task/config.sh.example` the template for `~/.config/task/config.sh`.

- **bin/pr-view** — PR panel for the terminal (fzf + delta): header with state, review, CI and size; Description, Checks, Comments and one entry per file with its diff in the preview; actions to open the task, review with Claude or open the browser. Used by Ctrl+click, `prefix ctrl+r` and gh-dash `V`.

- **bin/keymap-view** — text map of the keyboard layers, read from the keymap-drawer YAML of the keyboard repo (`prefix ctrl+k`).

- **nvim/** — LazyVim config (linked to `~/.config/nvim`). The dashboard images are third-party art and stay out of the repo (`nvim/.gitignore`).

- **bin/lazysql-kc** — opens lazysql with the `${env:NAME}` placeholders of its config filled from the macOS Keychain (service `lazysql`). `lazysql-kc set NAME` stores a secret, `lazysql-kc list` shows which are present.

- **lazysql/** — `config.toml.example`: template for `~/Library/Application Support/lazysql/config.toml`. The real file is not linked: lazysql writes saved connections into it.

- **gh-dash/** — `config.yml.example`: template for `~/.config/gh-dash/config.yml` (PR sections per org). The real file is not versioned because it has the work org and paths.

- **nushell/** — login shell (`~/Library/Application Support/nushell`)
	- `config.nu`: vi mode, Prom-Wiki colors, zoxide (`cd` = `z`), aliases.
	- `env.nu`: `PATH` and tool variables. `FZF_CTRL_R_COMMAND = ""` leaves `Ctrl+R` to atuin.
	- `autoload/direnv.nu`: runs direnv before every prompt, so `.envrc` also applies in the folder a new pane opens in.
	- `autoload/_fzf_integration.nu`: fzf key bindings for nushell (`Ctrl+T`, `Alt+C`), from [junegunn/fzf#4122](https://github.com/junegunn/fzf/issues/4122#issuecomment-2607368316).
	- `autoload/local.nu.example`: template for `autoload/local.nu`, machine-only variables (hosts, users, endpoints). Not versioned.
	- `atuin.nu`, `vendor/autoload/starship.nu`, `vendor/autoload/carapace.nu` and `~/.zoxide.nu` are generated by `install.sh` (`atuin init nu --disable-up-arrow`, `starship init nu`, `carapace _carapace nushell`, `zoxide init nushell`). Carapace loads from `vendor/autoload` so the fzf completer wraps it: `**<Tab>` goes to fzf, any other `<Tab>` to carapace (gh, docker, git, brew…).

- **starship/** — `starship.toml`: prompt with Prom-Wiki colors; shows the .NET version, the active AWS profile, the dev RDS tunnel (port 14330, only with `AWS_PROFILE=dev`) and the duration of commands over 3s.

- **atuin/** — `config.toml`: `Ctrl+R` history with fuzzy search, compact style and the `workspace` filter (current git repo); `Ctrl+R` again cycles global / host / session / directory / workspace.

- **git/**
	- `gitconfig`: delta as pager (line numbers, `n`/`N` navigation), `zdiff3` conflicts, moved lines highlighted, `pull --rebase`. Includes `~/.gitconfig.local`.
	- `gitconfig.local.example`: template for `~/.gitconfig.local` (work `includeIf`, signing key). Not versioned.
	- `ignore`: global gitignore.

- **lazygit/** — `config.yml`: diffs through delta, file tree, nvim as editor.

- **colima/** — `default.yaml`: template for new Colima instances (`~/.colima/_templates/default.yaml`), 4 CPUs / 8 GB, Rosetta enabled for amd64 images. Colima rewrites the instance file itself, so it is not linked.

## Secrets and machine-only settings

This repository is public. Credentials, hosts and company settings stay in files that are not versioned (`.gitignore` covers `*.local`, `local.nu`, `.envrc`, `.env`):

- nushell: `autoload/local.nu`
- git: `~/.gitconfig.local`
- per project: `.envrc` (direnv)
- lazysql and gh-dash: real configs stay outside the repo (only `*.example` templates here); database passwords live in the Keychain (`lazysql-kc set NAME`)
- gh account per folder: an `.envrc` with `export GH_TOKEN="$(gh auth token --user <login>)"` makes `gh` (and agents started there) use that account; the token comes from gh's keyring at load time

`install.sh` sets `core.hooksPath` to `.githooks/`: the pre-commit hook runs `gitleaks` on the staged diff and rejects URLs with an inline password (use `${env:NAME}`). Full scan:

```sh
gitleaks git . --no-banner --redact && gitleaks dir . --no-banner --redact
```

## herdr

Ghostty opens straight into herdr; closing the window only detaches, agents keep running.
Prefix is `ctrl+a` (herdr's default is `ctrl+b`; `prefix ?` shows every key).
AeroSpace keeps only `alt-h/j/k/l` (window focus); its workspaces, modes and infra script use `ctrl+alt+⌘` (sent by the keyboard's Fluxo layer), which leaves `alt+1..9` to herdr.

| Keys | Action |
| --- | --- |
| `prefix c` / `prefix n` / `prefix p` | New / next / previous tab |
| `prefix v` / `prefix -` | Split right / down |
| `prefix h/j/k/l` | Move between panes |
| `prefix z` | Zoom pane |
| `prefix w` / `prefix g` | Workspace picker / goto |
| `prefix shift+n` | New workspace |
| `prefix a` / `prefix shift+a` | Next / previous agent (sidebar is sorted by attention: blocked first) |
| `alt+1..9` | Switch to herdr workspace N (= task N) |
| `prefix shift+g` / `prefix ctrl+o` / `prefix ctrl+x` | New / open / remove git worktree (as a workspace) |
| `prefix o` | Jump to the agent from the last notification |
| `prefix b` | Toggle sidebar |
| `prefix f` | Floating shell popup |
| `prefix ctrl+g` / `prefix ctrl+d` | lazygit / lazydocker popup |
| `prefix ctrl+s` / `prefix ctrl+p` | lazysql (secrets from Keychain) / gh dash popup |
| `prefix ctrl+t` | Task picker: tasks, projects, zoxide folders (`ctrl-n` new task, `ctrl-x` close task) |
| `prefix ctrl+n` | Quick capture: one line into the current task's log, or the Inbox |
| `prefix ctrl+k` | Keyboard map (←/→ switch layers) |
| `prefix ctrl+r` | Panel of the PR of the focused pane's branch (`pr-view`) |
| Ctrl+click on a GitHub PR/issue link | Same popup for that PR/issue |
| `prefix [` | Copy mode (`v` select, `y` copy) |
| `prefix q` | Detach |
| `prefix shift+r` | Reload config |

### Keyboard (Crosses, ZMK)

The split keyboard ([zmk-for-crosses](https://github.com/KeveenMenezes/zmk-for-crosses), layout in `img/crosses.svg`) sends these shortcuts in one press from the home position:

- **Herdr prefix:** the key above the left pinky (left of `Y`) sends `ctrl+a`; it is the only herdr key on the base layer.
- **Mission Control:** the left pinky outer home key (left of `H`) sends `ctrl+↑`, like the Mac's F3 key.
- **Copy / paste:** the inner column under the left index sends `⌘C` (top row) and `⌘V` (bottom row).
- **Fluxo layer:** hold the left outer thumb (tapping it still gives sticky punctuation).
	- **Left hand, herdr:**
		- outer column: task picker · quick capture · keyboard map
		- top row: new tab · previous/next tab · split right · split down
		- home row: move between panes ← ↓ ↑ → (h/j/k/l) · zoom
		- bottom row: lazygit · lazydocker · gh dash · lazysql · PR of current branch
	- **Right thumbs:** next agent · previous agent · notified agent.
	- **Right hand, AeroSpace** (sent as `ctrl+alt+⌘`): workspaces on the same keys as the digits of the number layer (code 1 … scratch 9, web 0) and the service/windows/resize/move/infra modes; outer column: floating shell · workspace picker · goto.
- **Accents:** the sticky `Func` key, then one key for `ão` or `ões`. Other accents use the dead keys (`'`, `~`, `^` and `` ` ``) of the punctuation layer with the macOS "Brazilian – Pro" input source. macOS must see the keyboard as ANSI (`/Library/Preferences/com.apple.keyboardtype`, value 40); as ISO it swaps `` ` ``/`~` for `§`/`±`.
- **Trackball:** moving it turns on the Mouse layer for 450 ms after the last movement. Left home row in that layer: Snipe (slow, precise) · right click · Scroll (hold and roll the ball) · click · middle click. The base layer has no mouse keys: after a pause, nudge the ball first.
- **Repeat key:** the base layer's top outer-right key repeats the last key (double letters, repeated shortcuts).
- **AeroSpace vs herdr:** AeroSpace gets `ctrl+alt+⌘` from the Fluxo layer; `alt+1..9` (number layer + sticky Alt) switches herdr workspaces.

## Tasks

A task (ticket) is the unit of navigation; a project (repository) is only a layout recipe.

- **Folder:** `$TASK_ROOT/<ticket>-<slug>/` holds `TASK.md` (an Obsidian note when `TASK_ROOT` lives in a vault, and agent context: frontmatter, Context, Repositories, Decisions, Log), a `CLAUDE.md` that imports it, and one git worktree per repository on `feature/<ticket>/<slug>` (variants such as `-develop` get their own folder). A repository whose main clone is already on the task branch is linked instead.
- **herdr workspace** `<ticket> · <slug>`: an `agente` tab at the task root (sees every repository) plus one tab per repository with its layout. The layout comes from `~/.config/task/layouts/<repo>.sh` or the default, which leaves the run command typed (not executed) so open tasks don't fight over ports.

| Command | What it does |
| --- | --- |
| `task new <ticket\|-> "<title>" --repo R [--repo R2] [--base B] [--variant V]` | Folder, worktrees + branches, `.env*` copied, `TASK.md`, workspace |
| `task open <id>` / `task list [--all]` | Focus or build the workspace / list tasks with their herdr state |
| `task add-repo <id> <repo> [--variant V \| --branch B]` | One more worktree; the tab appears at once if the workspace is open |
| `task review <owner/repo> <pr> [--review]` | Task of a PR (ticket from the branch), creating it if needed; `--review` opens Claude on `/code-review` |
| `task new-from-issue <owner/repo> <issue>` | Task from an issue (title via `gh`) |
| `task capture [text]` | Line in the current task's log, else the Inbox |
| `task close <id>` | Refuses with pending changes; shows merge state; asks for the id; removes the worktrees (branches stay) and closes the workspace; `TASK.md` stays with `status: encerrada` |
| `task migrate [--apply] [--drop-links]` | One-off: moves loose sibling worktrees into task folders, leaving compatibility links at the old paths |

gh-dash keys: `T` open the PR's task, `I` review it with Claude, `V` PR panel, `N` (issue) new task.

### Claude Code setup

```sh
brew install herdr
herdr integration install claude   # session restore after herdr restarts (install.sh runs it)
```

`install.sh` also writes the official herdr skill (`herdr --skill`) to `~/.claude/skills/herdr/`, and the `keveen.workflow` plugin refreshes it on every herdr server start.

Then point the Claude Code status line at the script in `~/.claude/settings.json`:

```json
"statusLine": { "type": "command", "command": "~/.config/herdr/scripts/claude-statusline.sh", "padding": 0 }
```

The sidebar shows, for each Claude agent: state, where it runs, what it is doing (terminal title) and `model · ctx N%` (green < 50%, orange < 80%, red above, close to auto-compact). The tab bar shows the plan usage of the current 5-hour window, time until it resets and the 7-day usage; it disappears when there is no data.

## Usage

- Use the `aerospace/default-config.toml` for AeroSpace window manager customization.
- Import the VS Code settings and keybindings for a personalized editor experience.
- Install herdr (`brew install herdr`) and link `ghostty/` and `herdr/` into `~/.config/` (done by `install.sh`).
- Terminal tools: `brew install nushell starship atuin zoxide direnv fzf git-delta lazygit colima carapace gh lazysql lazydocker gitleaks`, then run `install.sh`.
